# KYTTU: Last Route Godot Edition

The Godot 4 edition of **KYTTU: The Last Route**, a first-person co-op horror game.

> **Status: semi-obsolete.** This Godot edition is being brought to a semi-stable state and will then be kept in
> maintenance mode only: bug fixes and build upkeep, no new features. Active development is moving to a Rust port of the
> game. Staging builds stay available (see [Downloads](#downloads)), and the code stays here as a reference and for
> anyone who wants to play or mod this edition.

You and up to a few friends explore a procedurally streamed facility of rooms, halls, stairwells, sewers and vents while a roster of 26 distinct hunters stalks the route. Find tools, hide, flee and rescue each other; if you are caught, you spectate until the party recovers or the run ends.

## Features

- **Endless procedural world.** A deterministic, seeded generator streams chunks of the facility, with district-specific textures, lighting, ambience and props. Maps are reproducible from a route seed.
- **26 hunters** with a shared perception, state-machine and capture brain. Each has its own gimmick, emotes and hard-mode abilities. Hunters are blocky models driven by data in `data/hunters/`.
- **Solo or co-op.** A solo run is a one-player room. Online rooms run on dedicated hosts started by a small Node service and are joined by a five-character code (ENet on desktop, WebSocket in the browser); there is also an always-open public route.
- **Items and survival.** Flashlight, taser, lockpick, crowbar, rescue axe, revive kits, backpacks, stamina and lamp battery, hiding in furniture and vents, resting and sleeping.
- **Night Watch.** A separate set of shift-style modes (office, bedroom, lure, mask, descent, open-air and more), also data-driven.
- **Difficulty levels** Relaxed, Standard and Hard. A Nightmare option is shown but not playable yet.
- **Accounts and saves** on the optional backend, with offline play when no server is reachable.
- **Modding.** Content packs can add or replace hunters, props, rooms, themes, death lines and more, with a validator and packer.
- **Input.** Keyboard and mouse, standard gamepads, rebindable controls, and experimental touch and XR tracks.

See [docs/QUICK_START.md](docs/QUICK_START.md) for the full controls.

## Downloads

The latest debug builds of `main` are on the [staging release](https://github.com/KyttuXD/LastRouteGodot/releases/tag/staging):
Linux, Windows, macOS (Intel and Apple Silicon) and Web. Every push to `main` replaces its files, so it is always the
newest build, not a versioned release.

## Open it in Godot

1. Install Godot **4.7** or newer (CI pins the exact version in `tools/build/setup_godot.sh`).
2. In the Project Manager choose **Import** and select `project.godot`.
3. Open the project and press **F5** to run.

If the editor reports `Identifier "X" not declared in the current scope`, the global class cache is missing. It is generated by the import scan and is not committed. Run one headless import, then reopen the editor:

```sh
godot --headless --path . --import
```

Deleting the `.godot/` folder is always safe; it is a cache.

## Build

Builds are produced by the GitHub Actions workflow [`.github/workflows/build.yml`](.github/workflows/build.yml). It runs on every push and pull request and exports debug builds for:

- Linux
- Windows
- macOS Intel
- macOS Apple Silicon
- Web

Each build is uploaded as a workflow artifact (they expire automatically). Notes:

- Artifacts are **debug builds** and include the admin overlay (key `0`).
- Linux downloads need `chmod +x` after extraction.
- macOS builds are ad-hoc signed, not notarized. Right-click the app and choose **Open** the first time.
- A separate job runs the backend tests and a fast subset of the headless Godot test suites.

To export locally, install the matching export templates and run, for example:

```sh
godot --headless --path . --export-debug "Linux Debug Tools" builds/KyttusLab-Linux-Debug.x86_64
```

The presets are listed in `export_presets.cfg`. More detail is in [docs/DISTRIBUTION.md](docs/DISTRIBUTION.md) and [docs/WEB_BUILD.md](docs/WEB_BUILD.md).

## Tests

Headless suites boot the real project and drive the actual scenes:

```sh
godot --headless --path . res://tests/scenes/validate.tscn
godot --headless --path . res://tests/scenes/validate.tscn -- sync layout   # a subset
GODOT_BIN=/path/to/godot ./tools/build/validate_all.sh                       # import + backend + all suites
```

Run suites as a scene, not with `--script`, so that autoloads are registered. See [docs/TESTING.md](docs/TESTING.md).

## Backend server (optional)

The game works offline. For online rooms, accounts, saves and updates, run the dependency-free Node service in [`backend/`](backend/README.md):

```sh
cd backend
npm test
```

Hosting, configuration and environment variables are documented in [backend/README.md](backend/README.md). The game client defaults to the public server at `https://lastroutegodot.games.kyttuslab.org`. Never commit secrets; the server reads them from a local `.env` file or the environment.

## Modding

Content packs can add hunters, props, rooms, themes, lines and other data without touching engine code. Start with [docs/modding/README.md](docs/modding/README.md); sample packs live in [`examples/mods/`](examples/mods/README.md).

## Repository layout

```text
game/       The game: scenes and scripts grouped by feature (autoload, menus, hud, player, hunters,
            world, network, night_watch, admin, mods, story, ...)
assets/     Runtime art imported by Godot
art_source/ Blender / Blockbench / texture sources (not exported)
data/       JSON content (themes, hunters, props, night_watch, story, ...)
tests/      Headless test suites, fixtures and smoke scenes
dev/        Playtest and look-development scenes
tools/      Build, export and content pipeline scripts
docs/       Documentation (index: docs/README.md)
backend/    Node service for rooms, accounts, saves and updates
platform/   Android plugin sources
examples/   Sample mod packs
```

The full map is in [docs/PROJECT_LAYOUT.md](docs/PROJECT_LAYOUT.md); the documentation index is [docs/README.md](docs/README.md).
