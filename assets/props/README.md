# 3D asset pipeline

Runtime models for LastRoute's 3D presentation layer (see `../../MIGRATION.md`).
Characters and interactables load through `game/hunters/view/model_slot.gd`.
Generated room dressing uses `game/config/prop_model_catalog.gd`, which maps
mechanical prop ids to the authored GLBs under `props/maze`, `props/mansion`,
`props/beach`, `props/nether`, and `props/prison`. Runtime catalog validation
rejects missing or mesh-less assets; `generic_prop.tscn` remains only as a
legacy editor/reference-layout fallback.

The blocky rebuilds in `props/blocky` are what gameplay (colliders, footprints) is derived from, but the detailed models in the other folders are
what is drawn for every type that passes the fit and cost screen: `PropModelCatalog.PREFER_ORIGINAL_PROPS` and its deny list, see
`docs/ORIGINAL_PROPS.md`. A new original model is picked up automatically for a type that has a blocky twin; run
`tools/props/original_fit_report.tscn` and `original_props` before relying on it.

## Scale convention

**1 grid tile = 1 meter = 1 Godot unit.** This lines up directly with
`game/world/generation/facility_generator.gd`'s integer cell coordinates: a generator
cell `(x, y)` maps to the 3D ground position `(x, 0, y)` (Godot is Y-up, so
the facility's 2D grid becomes the XZ ground plane, not XY). The 2D port's
own `GameConfig.TILE_SIZE` (16px) is the equivalent unit on that side — the
two are parallel, unrelated pixel/meter scales for the same grid, not a
conversion factor between them.

## Pivot convention

**Every prop's origin sits at its base center — flush on the floor at
`y = 0`.** Place a prop at a cell's world position and it stands on the
ground with no manual offset. This matches Blender's usual "object origin at
the base" habit for architectural/prop assets, so exports should need no
repositioning on import — just point the import at the same origin.

Concretely, for a prop whose visual height is `h`: its mesh/collision should
be centered `h / 2` above the object's own origin, so the object origin
itself stays at floor level. Retained Blender/Blockbench sources and exported
GLBs follow this rule; runtime collision stays in Godot where gameplay needs a
simpler shape than the visible mesh.

## Import format

**Export to glTF 2.0 (`.glb`).** Retain the editable `.blend` or `.bbmodel`
beside the generated asset source, but treat GLB as the shipping contract.
Godot imports it natively, and the repository builders normalize transforms,
floor pivots, materials, texture filtering, and preview renders consistently.
Forward/up axes remain Godot +Y up and -Z forward after Blender export.

it in anywhere.

## How the game loads these files

`game/hunters/view/model_slot.gd` is the only place that reads this folder. It has
two loading strategies, and which one applies depends on how the slot is
*used* in-game, not what it represents:

- **GridMap items** (`wall_block.tscn`, `floor_tile.tscn` — anything painted
  across a tiled floor via `GridMap.set_cell_item`) go through
  `ModelSlot.load_gridmap_item()`. GridMap needs raw `Mesh`/`Shape3D`
  *resources* up front to build its `MeshLibrary`, not a scene to instance
  per-cell, so this walks the scene's node tree, grabs the first
  `MeshInstance3D` found (for its mesh + local transform) and the first
  `CollisionShape3D` found (for its shape + local transform), and discards
  the rest of the scene.
- **Everything else** (characters, interactables — anything that gets its
  own node in the scene tree) goes through `ModelSlot.instantiate()`, which
  just instances the whole `.tscn` as-is. A real model here can be as
  complex as it needs to be — skeleton, `AnimationPlayer`, multiple mesh
  parts, sub-scenes — the game makes no assumptions about its internals.

### Scene structure ModelSlot expects

- **GridMap items**: needs at least one `MeshInstance3D` somewhere in the
  scene tree (found by *type*, not by node name — so an FBX/glTF import
  naming its mesh node after the source object, e.g. `WallBlock`, works
  fine, no renaming required). A `CollisionShape3D` is optional but expected
  for anything the player should collide with — see import settings below
  for how to get one out of an import automatically.
- **Everything else**: no required structure at all — the scene is
  instanced whole. Its root should be a `Node3D` (or subclass) so it can be
  added as a child of the game's own wrapper node. An `AnimationPlayer`
  anywhere under it is optional — see "Animations" below.

## Animations

The player and hunter controllers each look for an `AnimationPlayer`
anywhere under their instanced model (`ModelSlot.find_animation_player()` —
found by type, same reasoning as the mesh/collision lookups above, so it
doesn't matter what the import named it) and, every frame, ask it to play a
clip named after the current movement/AI state
(`ModelSlot.play_if_available()`). Both lookups are fully optional: no
`AnimationPlayer`, or no clip with that exact name, is a silent no-op, not
an error — true for every placeholder in this folder today, since none of
them have any animation at all. Naming an animated model's clips to match
is the entire remaining step to make it move:

| Model | Clip names it should have |
| --- | --- |
| `characters/player.tscn` | `idle`, `walk`, `sprint`, `crouch` |
| `characters/*.tscn` hunters | `idle`, `walk`, `sprint`, `chase`, `crouch`, `stun` |

A hunter's clip is picked from her `HunterBrain.state`: `IDLE` → `idle`;
`WANDER`/`INVESTIGATE`/`SEARCH` → `walk` (she's purposefully headed
somewhere, just not at chase urgency); `CHASE` → `chase`. An active
`HunterBrain.stun_timer` overrides those states with the looping dizzy/head-
roll `stun` reaction, including the recovery after a failed attack. The player's clip
is picked from whichever of `idle`/`walk`/`sprint`/`crouch` matches its
current `movement_mode`, or `idle` while not moving or frozen (e.g. during
the capture/escape struggle).

## Swapping in a real model

1. Export the real asset as `.fbx` from Blockbench (or `.glb`/`.fbx` from
   Blender): origin at base center (floor-flush pivot, see "Pivot
   convention" above), real-world scale (1 unit = 1m, see "Scale
   convention" above).
2. Drop the file anywhere under this folder (alongside the placeholder it's
   replacing is fine) and let Godot import it.
3. For a **GridMap item** (wall/floor) that needs collision: select the
   imported file in the FileSystem dock, open the **Import** tab, and under
   **Meshes** set **Physics → Body Type** to `Static` and **Shape Type** to
   `Trimesh` (exact geometry — fine for static level geometry at this
   scale) or `Decompose Convex` if you'd rather have a simplified collision
   shape for a complex prop. Reimport. This makes the import generate a
   `StaticBody3D`/`CollisionShape3D` pair alongside the mesh, which
   `ModelSlot.load_gridmap_item()` picks up automatically (again, by type —
   the generated node's name doesn't matter). This dock is the same for FBX
   and glTF imports — it's part of Godot's generic scene-import pipeline,
   not format-specific.
4. Open the placeholder `.tscn` this model replaces and either:
   - **Simplest**: delete the placeholder's `MeshInstance3D` child, drag the
     imported model in as a new child instance instead, and re-check the
     pivot/transform lines up with `y = 0` at the object's origin (nudge the
     instance's own transform if the export's pivot was slightly off,
     rather than touching the placeholder's other nodes).
   - **Alternative**: replace the whole `.tscn`'s contents outright — the
     only requirement is the root stays a `Node3D` and, for GridMap items, a
     `MeshInstance3D` is reachable somewhere under it. Keep the file at the
     same path; nothing in `src/game_3d/` references node names inside
     these scenes, only the file path.
5. If the model's textures come out blurry (common with Blockbench's
   pixel-art-style textures under Godot's default linear filtering): select
   the imported texture resource, open **Import**, and set **Filter** to
   `Nearest`, then reimport.
6. If the model is animated (player or a hunter): name its clips per the
   "Animations" table above. Nothing else to wire up — `ModelSlot` finds the
   `AnimationPlayer` and the game starts driving it by name automatically.
7. Open `reference_layout.tscn` and check it still reads correctly at scale
   next to everything else that hasn't been replaced yet.
8. Run the game (`game/main_3d.tscn`) and confirm the model shows up (and,
   if animated, moves) where expected — no code changes should be needed
   for any slot in the table above.
